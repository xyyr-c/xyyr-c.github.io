一道基础c++ pwn的学习

学过c但没学过c++，遇到了一道基础的c++pwn，快速整理与c语言对比学习一份基础

c++基础

基本输入与输出

  • std::命名空间内，cout <<来输出，cin >> 来输入，cerr << 为标准错误的提示
  • std::endl; // 输出换行 + 刷新输出的缓冲区（c语言中的fflush）

缓冲区作用:减少系统调用的次数，缓冲区满或刷新时再执行io

取址与引用

  • c++中对于变量定义时，用&作为引用，其必须绑定对象且固定绑定，可以作为普通变量使用。

  • 在已经定义好的变量前，仍然是取地址，如以下仍然是取地址

命名空间

  • c++中用namespace把名字分组来避免冲突，同名会合并，但里面定义的变量等重定义会报错，函数可以重载，namespace定义的名字不同和其他同名实体共存
  • 对于命名空间的引用，可以采用以下三种方式
  • 嵌套命名空间（解决重名的问题）

函数

  • c++允许存在参数列表不同的同名函数，编译器根据实参类型选择对应的函数。如
  • 默认参数，需要从右往左连续给。
  • mangling机制，编译器需要把参数类型也编进符号名里，这个机制叫做name mangling(名字改编)，会编译出很长的符号名。
  • 使用extern “C”来使得c代码可以调用c++写到的函数，不被mangling，直接用指定的名字。
  • 构造函数：名字与类名相同，但没有返回值；对象创建时自动调用
  • 初始化列表：在对象创建时将对应参数赋予初始化的初值，初始化顺序按照声明的顺序
  • 析构函数：对象销毁时自动调用（离开作用域、delete、异常展开、程序退出时全局对象），不能有参数，不能重载
  • 基类：被其他类继承的类，也称父类。该类的函数必须是虚函数才能够被继承，这种类的析构应该声明为virtual。如果不声明，那么子类的析构函数就不会被调用，如果子类的分配的内存是在子类析构函数中执行的，则该部分内存资源不会被释放。（子类不用是虚函数，但是父类需要是）
  • 拷贝构造/复制运算符

用new分配的内存空间需要在析构函数中释放，否则会导致异常。

new与delete

  • new与c语言中的malloc相似，但是使用更为方便。可以直接分配定义好的类型的大小，不用再sizeof。注意数组要用[]
C C++ 说明
malloc(sizeof(T)) new T new 会调用构造函数
malloc(n * sizeof(T)) new T[n] 会多申请 8 字节存元素个数
free(p) delete p delete 会调用析构函数
free(p) delete[] p 数组必须用 delete[]
失败返回 NULL 失败抛 std::bad_alloc 默认不返回 NULL
calloc new T[n]() 零初始化
  • 看到了这里，去看看了c++中的struct，它对struct做了增强，不再需要typedef 定义别名，直接能用struct定义的名字创建变量
  • 64位下存元素个数是8字节，32位常规是4字节，但是特殊情况下会被规定为8字节
  • new的本质实现还是malloc，还可以打malloc_hook，delete会先调用析构（析构不知道是啥，后面看），可能有更多的free，称为析构链。

类与对象

  • C中的struct只能存放数据，C++ 的 class 能装数据 + 函数，并且有访问控制、构造/析构、继承、多态。class默认私有，类中的私有函数需要借用公有的成员函数间接调用。也就是创建该类的对象，也不能直接调用私有的函数，必须通过公有。protected权限除了外部直接用类调用，别的都可以。
  • 静态公有函数可以通过类名直接调用，不需要对象
  • 友元，把自己类的私有成员开放给零一个类，单向不可继承。这些都属于访问控制
  • this指针，类的成员函数里会有一个不显示的this参数指向该函数的对象，调用时用this来调用，编译后该this作为函数的第一个地址。（劫持虚函数时rdi就是对象地址）
  • 类中的static成员，分配在静态内存中，所有对象共享一份，静态成员函数没有this。

疑问：这个定义为什么必须在外面，这种类型的数据如何使用，如何创建对应的对象并使用，会存在冲突吗，有互斥吗

类内用来声明，类外定义才会真正分配内存，c++17之后可以用inline static int count来类内定义且分配，其本身没有互斥机制，互斥需要自行实现加锁；inline：允许多个翻译单元里有相同的定义，链接器只保留一份。

  • sizeof计算对象的大小,虚函数存储时，只多一个vptr的虚指针，空类为1字节，保证每个对象有唯一的地址。

多态类的 vtable 通常由编译器生成，放在只读数据段，如 .rodata 或 .data.rel.ro

多态与虚函数

  • 运行时动态绑定，通过vptr指针指向vtable表项

    vtable表项存储在data上方的.rel.ro处

  • 多继承与thunk
    thunk是一段用于转换调用约定/参数/指针，然后跳转到目标函数的中间代码，常用于跳转this指针、虚基类指针、返回值指针

    如类C继承了A与B

    C 对象：
    +0 : vptr1 -> Vtable for C (A-in-C) // 主 vtable
    +8 : vptr2 -> Vtable for C (B-in-C) // 次 vtable
    +16 : C 自己的成员…

    会有两张vtable表,第一个是主表,继承了A的函数,如果C有新的定义的函数,也会出现在这张表;继承了几个类,就会有几个表

  • override显示证明重写覆盖的函数,final代表禁止被继承
